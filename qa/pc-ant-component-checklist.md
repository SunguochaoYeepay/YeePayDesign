# PC Ant 组件验收清单

适用平台：`admin-pc-ant`。移动端不使用本清单。

## 控件

- Select 是否使用统一箭头和打开态，而非浏览器原生箭头；展开菜单的选项是否为纵向满宽的 `ui-option`，未被并排按钮或 Chip 替代。
- Radio 是否使用 `label > input[type=radio] + ui-radio-mark` 的原生语义，而非矩形 `button` 模拟；选中态是否为主色，且禁用/错误状态清晰。
- Steps 的 `finish` 是否使用主色，未误用成功绿。
- DatePicker 是否使用 `CalendarOutlined` 和统一面板，未展示浏览器原生日历。
- Tooltip 是否使用 `InfoCircleOutlined` 等已登记图标，未使用文字 `i` 或 Emoji。
- 每个 `data-icon` 是否都存在于本地 Ant SVG 精灵，且没有 CSS 伪元素绘图。

## 状态

- Loading、Empty、Error 是否与业务主体互斥。
- 所有带 `hidden` 的状态组件是否真的不占空间。
- Error 是否具备可执行的恢复动作。

## 图标与平台

- 所有图标是否均能映射到 `ANT-PC-ICON-REGISTRY.md`。
- Page Spec 是否标记 `ui.platform: admin-pc-ant`。
- 页面是否没有混入移动端尺寸、手势或 Vant 组件规则。

## 表单排版

- 当前 Page Spec 的 `family`、模板、菜单路径和排除项是否与本次业务需求一致，未沿用上一场景。
- 单列表单是否保持标签右对齐和足够控件宽度；复杂分组表单是否使用标签在上、2/3/4 列网格与跨列字段，而非强行把所有字段塞进两列。
- Page Spec 是否声明 `form.fieldLayout` 与 `form.actions.placement`，且操作栏选择由字段布局决定。
- 单列字段堆叠的提交按钮是否紧随最后一个字段，并与输入控件左边对齐；不得对齐标签列或内容卡片左边。
- `form.sideIllustration` 是否只保留 Steps 作为页面任务标题，未重复渲染页面 H1、描述或 Step 1 标题。
- 多列/多分组的页面级长表单是否使用底部悬停操作栏，次操作在左、主操作在右；不得将页面级主操作放入任一字段列。
- 分组表单是否使用有语义的信息组 Card；内容区有两个或更多任务块时，块间是否露出 16px 的灰色承载面，而非连续白底。
- 侧插图是否为真实资产或图片形态占位，且在 768px 以下隐藏；不得用普通图标充当插图。
- 上传流程是否按上传、校验复核、确认、完成闭环，复核表是否为只读结构化数据。
- 表单提交失败是否滚动并定位到第一个错误字段，同时保留已填写数据。
- 长业务规则、数据源说明和服务端校验过程是否保留在 Spec，而非渲染为字段旁的竖排文本。
- 当前 Steps 是否为 `process`，后续步骤是否为 `wait`，已完成步骤才使用 `finish`。

## 详情与结果

- 少量字段是否使用无滚动的 Modal；需要保留来源列表和更多信息时是否使用 Drawer；编辑是否跳转独立 Form。
- 独立详情是否采用三列 Descriptions，长字段是否跨列且没有缩小字号硬塞。
- 连续关联的信息组是否使用 Anchor，相对独立的信息组是否使用 Tabs，且没有混用两种导航。
- 内嵌 Table 是否只表示从属明细，未混入筛选、分页、批量操作、嵌套展开或独立行跳转。
- 结果是否使用 Ant Result 状态语义，并按状态图标、标题、说明、动作、可选摘要、可选调研的顺序组织。
- 失败结果是否提供返回修改、重试或返回列表等恢复动作；满意度调研是否只出现在核心成功流程且不阻断操作。
