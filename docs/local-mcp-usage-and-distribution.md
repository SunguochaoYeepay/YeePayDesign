# 本地 MCP 使用与分发指南

## 目标

本框架的目标不是要求业务人员理解页面类型、组件或代码，而是让他们在已选定的原型项目中
直接描述业务需求，获得可访问的后台预览。

```text
选择后台原型项目 -> 输入业务需求 -> AI 调用受控 MCP -> 生成预览 -> 人工验收
```

## 角色边界

| 角色 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 业务人员 | 目标、字段、规则、数据、验收标准与参考图 | MCP、模板、Page Spec、组件、文件路径、构建命令 |
| AI | 选择已支持页面族、补充缺失业务问题、编写 Page Spec、调用 MCP | 手写 Vue、HTML、CSS、Shell 或派生产物 |
| 框架维护者 | Context Pack、渲染器、MCP、Skill、测试与版本发布 | 为单次页面手工改生成制品 |
| 项目管理员 | 安装框架、登记项目、配置客户端与分配项目访问 | 替业务人员描述需求 |

## 业务人员的日常用法

前提：管理员已完成一次性安装，并在 Codex、Cursor 或 Claude Code 中打开了一个已初始化的
后台原型项目。

业务人员只需新建任务并输入业务需求，例如：

```text
结算查询

财务人员需要查询近期结算单，核对结算金额与打款状态。支持按结算日期、结算单号、商户和
结算状态查询；列表展示结算单号、商户、金额、状态和操作。无数据时提示用户修改筛选条件。
```

业务人员不输入项目 ID、MCP 名称、页面类型、模板、Vue、HTML、CSS、输出目录或构建命令。
当业务信息缺失时，AI 只能追问缺少的业务事实，例如“请提供列表的示例数据”，不能追问
技术实现细节。

生成完成后，业务人员只验收预览链接中的视觉和交互。发现问题时，记录为“业务字段遗漏”、
“规则错误”或“基础样式问题”；不得直接修改 `page-content.html`、`checklist.md` 或
`preview.html`。

日常操作和验收口径见[后台原型使用指南](business-user-guide.md)；可直接复用的业务回归
需求见[已验收能力与回归提示词](../prompts/acceptance-baseline.md)。

## 本机 PoC 配置

当前 PoC 由四部分组成：

1. 原型框架工程：包含 Context Pack、Vue/Ant runtime、渲染器与 MCP 服务。
2. 本地 MCP 网关：默认监听 `http://127.0.0.1:4318/mcp`，仅本机可访问。
3. 客户端 Skill：把自然语言业务需求转换为受控的 MCP 调用，不向业务人员暴露内部步骤。
4. 项目级 `AGENTS.md`：在已初始化工作区内禁止通用 AI 直接创建 HTML/CSS/JS，并强制走
   本地原型 MCP。

在 Codex 中，必须打开实际的原型项目目录再新建任务。若在无 `AGENTS.md` 的普通项目中
提需求，通用前端生成流程可能会绕过 MCP 并直接写 HTML/CSS/JS；此时应停止任务，切换回
正确工作区。

### 管理员一次性安装

当前 PoC 的管理员流程：

```bash
npm install
npm run build:vue-ant-runtime
npm run mcp:gateway
```

然后在 AI 客户端登记本地 MCP 地址，并初始化一个可写的原型项目。项目初始化会放入固定的
`context-packs/`、`design-system/`、`shell/` 和 `tools/` 运行资源。

具体 MCP 配置、项目登记和项目初始化顺序见 [MCP 接入说明](../mcp/README.md)。

## 不同客户端的适配

MCP 只提供工具，不会自动规定 AI 如何使用工具。因此每个 AI 客户端都需要对应的行为规则。

| 客户端 | MCP 接入 | 行为规则 | 业务人员入口 |
| --- | --- | --- | --- |
| Codex | 本地命令或本地 HTTP MCP | 全局 Skill + 项目 `AGENTS.md` | 在已选项目中直接输入业务需求 |
| Cursor | MCP 配置 | Cursor Rules | 在已选项目中直接输入业务需求 |
| Claude Code | MCP 配置 | `CLAUDE.md` | 在已选项目中直接输入业务需求 |

三种规则文件应由同一份“生成策略”生成或同步维护，不能分别手工演化出不同规则。

## 当前限制

- 当前正式 MCP 快速入口支持 `form`、`list` 和 `detail`；`result` 仍只作为受控流程的提交结果，不接受独立业务页面生成。
- 业务人员必须在正确的后台原型项目中发起任务；当前 PoC 尚未提供项目选择界面。
- 复杂需求必须拆分。包含角色权限、真实导出、异步任务、详情多标签、后端处理流程的需求，
  不能伪装成一张列表页面。
- 当前服务仅监听本机回环地址，不可作为局域网或公网服务使用。

## 面向他人分发的目标形态

当前的绝对路径、LaunchAgent、本地项目登记文件和全局 Skill 都是单机 PoC 配置，不能直接
复制给其他人。分发版本应提供安装包，而不是让每个人手工配置。

目标命令：

```text
admin-prototype setup <项目目录>   初始化项目与项目级规则
admin-prototype doctor             检查本机依赖、MCP 与运行资源
admin-prototype serve              启动本地 HTTP MCP 网关
```

目标交付物：

1. 可版本化的原型引擎包。
2. Codex Plugin，内含 Skill、MCP 配置与项目初始化入口。
3. Cursor、Claude Code 的规则适配文件。
4. 一份共享生成策略和回归样例库。
5. 项目选择与访问控制机制，替代向业务人员暴露项目 ID。

在上述能力完成前，当前版本应定位为“可验证的本地 PoC”，而非可直接面向团队发布的通用
插件。

## 故障判断

| 现象 | 原因 | 处理方式 |
| --- | --- | --- |
| AI 说要创建 HTML、CSS、JS | 未加载正确工作区规则或 Skill | 停止任务，在已初始化原型项目中重新发起 |
| 报告项目未初始化 | 项目缺少固定运行资源 | 由管理员初始化项目后重试 |
| 构建失败 | Page Spec 或能力组合不符合契约 | 修正业务映射或框架规则后重新构建，不手改制品 |
| 页面缺业务字段 | 业务需求到 Page Spec 的覆盖遗漏 | 修正 Skill、Context Pack 或渲染器，再重新生成 |
